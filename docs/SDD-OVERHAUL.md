# SHINY BURROWS — Bonanza-Inspired Gameplay Overhaul

## Objective

Transform Shiny Burrows into a modern spiritual successor to California Gold Rush: Bonanza!, preserving our original mole, 2.5D art direction and TypeScript architecture.

**The previous modernization roadmap is superseded for gameplay scope.** Bonanza's core gameplay systems are now the primary design reference, not optional inspiration.

Use the existing five analysis documents and the privately extracted Bonanza reference materials as research sources.

Implement original systems independently. Never copy or ship Bonanza's source code, graphics, level maps, audio or text.

## 1. Mining and movement overhaul

### Three-direction digging

Replace four-direction excavation with exactly three directions:

- Left
- Right
- Down

Upward movement must never dig terrain.

Up is reserved for climbing existing ladders and other explicitly designed traversal features.

Preserve automatic excavation when holding a movement direction against diggable terrain.

Maintain:
- Perfect uniform square grid
- One-cell mole
- Two-hit ordinary dirt
- Harder terrain durability
- Terrain regeneration rules
- Grid-aligned collisions
- Keyboard, mouse and touch compatibility

Update tutorials, input indicators, gameplay tests and level layouts.

### Fix automatic ladder generation

Investigate the current ladder-placement behavior.

**Bug:** leaving a ladder horizontally can automatically create an unintended ladder in an adjacent cell.

Required invariant:

A new ladder segment may be generated ONLY when the character actually moves vertically downward into a new grid cell and that movement satisfies the automatic ladder-placement rules.

Ladders must NOT be generated by:
- Moving horizontally off a ladder
- Changing horizontal cells while touching a ladder
- Simply entering or leaving a ladder cell
- Standing still
- Repeated collision-resolution events
- Climbing upward
- Falling within a previously processed cell

Track actual cell transitions rather than inferring ladder creation from proximity or movement intent.

If falling must generate ladders, handle it as a valid downward cell transition exactly once per cell.

Add regression tests for all these cases, including diagonal movement, landing, falling past ladder junctions and changing directions during climbing.

## 2. Implement the core Bonanza gameplay systems

Use the reverse-engineering report to identify and prioritize the complete baseline gameplay mechanics.

### Mining and world

- Multiple terrain types and durability
- Gold veins with varied value
- Hidden gold deposits and discovery
- Fog of war and progressive reveal
- Distinct underground strata
- Author-designed levels
- A reusable mine-generation system for Endless Mode

### Environmental gameplay

- Falling boulders
- Collapsing terrain
- Stable and unstable ground
- Environmental hazards based on the confirmed Bonanza systems
- Supports and protective structures
- Explosives and terrain interactions
- Clear danger warnings and recoverable route choices

### Equipment and economy

- Gold rewards and collection
- Upgradeable mining equipment
- Useful shop inventory
- Equipment effects on exploration
- Meaningful upgrade progression
- Resources and consumables where justified

Evaluate Bonanza's backpack capacity, stamina, and cash-out mechanics explicitly. Design modern equivalents if they improve strategic depth without creating repetitive waiting or unnecessary trips.

### Other baseline systems

Inventory all remaining confirmed Bonanza gameplay features, including enemy behavior, objectives, unlocks, special rewards and failure states.

Classify each as:
1. Implement faithfully in gameplay principle
2. Modernize
3. Adapt for a specific mode
4. Exclude with a documented reason

Do not silently omit an entire core system merely because the previous roadmap deferred it.

Exclude supernatural themes from the final aesthetic. Replace them with grounded mining hazards where functionally appropriate.

## 3. Story Mode

Create a structured campaign using handcrafted levels.

Requirements:

- Sequential mine progression
- Carefully designed maps and route choices
- Increasing difficulty and environmental complexity
- New mechanics introduced gradually
- Gold objectives and optional rewards
- Upgrade economy between stages
- Distinct level identities
- Clear success and failure conditions
- Saved progress
- Replayable completed levels
- No softlocks or mandatory premium mechanics

Rework the three existing prototype mines as the opening campaign stages.

Design a scalable campaign structure. Do not arbitrarily generate dozens of unreviewed levels.

## 4. Endless Mode

Implement a separate, repeatable survival-mining mode.

### Generation

- Deterministic seeded generation
- Progressive generation of deeper mine sections
- Variable gold distribution
- Increasing hazard density and complexity
- Guaranteed mechanically valid routes
- Stable streaming/unloading of old sections
- No broken ladders or inaccessible mandatory paths

### Progression

- Start each run with a defined equipment loadout
- Dig as deep as possible
- Earn gold and make meaningful upgrade decisions
- Survive environmental hazards
- Reach greater depths to obtain higher scores
- End runs through a clear failure condition
- Preserve personal records between sessions

Define separate permanent progression and run-specific resources so Story and Endless cannot accidentally corrupt one another.

### Scoring

Primary score: maximum depth reached.

Secondary statistics:
- Total gold collected
- Tiles excavated
- Time survived
- Optional efficiency achievements

Maintain a single canonical best score.

Integrate YouTube's `ytgame.engagement.sendScore()` where available, with the saved best score matching the submitted record.

Use local best-score presentation and official YouTube score functionality. Do not implement an unauthorized external leaderboard backend.

Preserve the existing stack:

Introduce modular systems for:
- Game mode rules
- Level definitions
- Procedural generation

- Progression

Do not rewrite the entire game or introduce a new engine.

## 7. Development procedure

Implement this overhaul incrementally.

Milestone A: Fix the ladder bug and introduce three-direction mining.

Milestone B: Gold deposits, discovery, fog of war and revised terrain.

Milestone C: Environmental hazards, boulders, collapses, supports and tools.

Milestone D: Equipment, inventory, shop and progression redesign.

Milestone E: Story Mode, level objectives and handcrafted maps.

Milestone F: Endless Mode, procedural generation, survival rules and scoring.

Milestone G: Persistence, YouTube SDK, performance and certification testing.

Platform abstractions and save-schema design should begin early enough to prevent gameplay architecture rework.

For each milestone:
1. Produce a concise implementation design.
2. Modify existing code incrementally.
3. Add deterministic unit and browser regression tests.
4. Verify existing mechanics that should remain unchanged.
5. Validate gameplay interactions and edge cases.
6. Run build, typecheck, lint and relevant test suites.
7. Report implemented features, known limitations and remaining work.

Start implementing **Milestone A immediately**.

After completing Milestone A, provide the code changes, test results and a concrete plan for Milestone B.

Do not claim a system is complete unless its behavior and tests demonstrate it.
